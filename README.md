## 方案声明

**报告里的每一个数字，都由确定性代码算出，不由 LLM 生成。**

```
analysis_flow 中的步骤分两类：

  🔢 metric 步骤  →  pandas 确定性计算  →  数字 100% 可复现、可验算、可溯源
  🧠 llm 步骤     →  只接收算好的指标，不接触原始数据 → 只负责归因和建议
```

这条设计同时回答了题目里最难的一问——**"如果 AI 员工分析结果错误，企业为什么应该相信它？"**

> 可信度不来自"模型不会错"，来自"错了能被发现、能被定位、能被修正，且同样的错不会犯第二次"。
> 我们不承诺 AI 不出错，我们承诺：**数字不会错、结论可验算、错误能定位、责任始终有人担。**

## 核心观点速览

### Skill 到底是什么

| | 本质 |
|---|---|
| **Prompt** | 一次性指令，无状态、无契约——**话术** |
| **Workflow** | 固定编排的执行路径，确定但不灵活——**流程** |
| **Agent** | 拥有工具和自主决策能力的运行时——**执行者** |
| **Skill** | 被结构化封装、可版本管理、可评测的岗位经验资产——**知识包** |

> Agent 是员工，Skill 是他受过的岗位培训。
> 换个员工，培训还在；同一个员工，可以受多项培训。
> **企业真正稀缺的从来不是能干活的 Agent，而是懂行的 Skill。**

### 三层防错，各管一段

| 层 | 能抓什么 | 抓不到什么 | 处置 |
|---|---|---|---|
| **四道校验闸** | 结构、引用、语法、可执行性 | 语义是否讲得通 | 硬拦截 |
| **模型自检** | 语义错误、口径歧义、边界情况 | 会误报 | 仅提示 |
| **人工确认** | 是否符合本公司实际业务 | — | 最终裁决 |

Demo 里有一个实测案例：生成的 Skill 出现 `人均关闭商机 = 平均销售周期天数`——
语法合法、变量都存在、**四道闸全部放行**，但业务上是两个毫不相关的概念。

**这就是为什么人工确认环节是特性而不是缺陷。**

## 三分钟看懂 Demo

```bash
cd demo
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
./.venv/bin/uvicorn app.main:app --port 8000
```

浏览器打开 http://localhost:8000 （无需 API Key 也能体验，此时数值仍真实计算）

最值得看的三幕：

1. **故意把分析流程改成引用一个不存在的字段** → 闸② 精确报出「步骤 S1 引用了未定义的字段『退货订单数』」
2. **点开报告里任意一个数字** → 展开显示公式、依赖字段、数据行数
3. **上传一份缺列的 CSV** → 明确拦截，并告诉你缺什么、从哪个后台页面导出

完整演示脚本见 [demo/README.md](demo/README.md#三分钟演示脚本)。

## 项目规模

| | |
|---|---|
| 后端代码 | ~4,500 行 Python |
| 前端 | 551 行单页 HTML（Tailwind CDN，无构建步骤） |
| 自动化测试 | 64 项（执行链路 34 + 四道校验闸 30） |
| Golden Set | 4 组标准用例，五维评分卡 |
| 预置 Skill | 3 个（电商直播 / 销售漏斗 / 零售门店） |
| 文档 | 3 份，约 2 万字 |

技术栈：FastAPI + pandas + Pydantic + SQLite + 原生 HTML。
LLM 层做了网关抽象，支持 Claude 与任意 OpenAI 兼容接口，换供应商改三行配置即可。
